# Правила командной разработки / Топтық жұмыс ережелері

1. `main` — согласованная ветка; изменения вносить через отдельные ветки и PR.
2. Названия веток: `docs/...`, `feature/...`, `fix/...`.
3. Описывайте в PR цель, изменённые файлы, способ проверки и риски.
4. Для изменений архитектуры оформляйте новый ADR в `docs/adr/`; старые решения не стирайте.
5. При смысловых изменениях основной документации обновляйте и соответствующий казахский перевод.
6. Не помещайте секреты, пароли, реальные персональные данные и файл `.env` в Git.
7. Перед merge проверяйте ссылки в Markdown, схемы Mermaid и согласованность терминов.
8. Сначала документация и план; работающий код появится в отдельной фазе.

## Термины
RU «модульный монолит» = KK «модульдік монолит»; «СУБД» = «ДҚБЖ»; «связь многие ко многим» = «көптен-көпке байланыс»; «запись на курс» = «курсқа тіркелу»; «прогресс» = «оқу барысы».
