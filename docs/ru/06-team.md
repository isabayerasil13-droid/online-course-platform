# 6. Команда и процесс работы

## Планируемая команда: 3–5 человек
- Backend: модели, бизнес-правила, права и API.
- Frontend: страницы курсов, уроков, входа и прогресса.
- QA / дизайн: тест-кейсы, интерфейс и проверка сценариев.
- Координатор: интеграция, ревью, документация и защита.
Несколько ролей может выполнять один участник.

## Предлагаемое распределение для 4 человек
| Участник | Первичная ответственность |
|---|---|
| 1 | Accounts, авторизация, общий Django-каркас |
| 2 | Courses, Lessons, категория и материалы |
| 3 | Enrollments, Assignments, Progress, модели PostgreSQL |
| 4 | UI, тесты, документация, демонстрация |

Распределение условное: реальные имена и задачи команда утвердит отдельно.

## Правила совместной работы
Каждая задача — отдельная ветка, понятный commit и Pull Request; код проверяет другой участник. Изменения модели согласуются заранее; файл ADR обновляется при новых архитектурных решениях. Описание PR содержит способ проверки. Русские и казахские документы поддерживаются согласованно.

## Минимальные критерии качества
В одном модуле не должна скрыто реализовываться логика другого; проверки прав обязательны; ссылки на удалённые сущности корректны; основные операции покрыты тестами; секреты не попадают в репозиторий.
